## Retained Linux x64 cohort

tarballs, and the direct-browser tarball. A local build uses the installed
version plugin's supported `UV_DYNAMIC_VERSIONING_BYPASS` for candidate metadata
without creating or pushing a release tag. Derive that value through
`scripts/release_version.py`, not by copying the npm suffix into Python metadata.
This override is for retained preparation artifacts only; tagged publication
continues to use the existing guarded release workflow.

From the preparation commit, after installing the documented development
dependencies:

```bash
node js/build.mjs
npm run build:wasm
python3 scripts/verify_wasm_assets.py
cargo build --release
candidate_python=$(python3 -c 'from scripts.release_version import parse_tag; print(parse_tag("xyg-v0.6.0-rc.1").python)')

python3 scripts/check_release_version.py --tag xyg-v0.6.0-rc.1
python3 scripts/verify_wheel.py dist/rc-0.6.0-rc.1/*.whl --expect-native --require-wasm
```
