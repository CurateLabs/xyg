# XYG 0.6.0 publication readiness — 2026-10-23

**Status: not accepted for public publication.**
[#108](https://github.com/CurateLabs/xyg/issues/108) remains the acceptance
authority. Preparation, schema qualification, a green required CI aggregate,
and registry access each establish only their stated scope.

## Completed prerequisite work

- XYG owns the result-disposition ledger. Ledger version 2 includes explicit
  source/target/cost tables for Core `bfs_depth` and `dijkstra_cost`, with UUIDs
  preserved and no fabricated paths. Unsupported schema versions retain their
  stable error code and name the schema and next action.
- [The compatibility declaration](../graphforge-compatibility.json) binds
  authentic Core `0.6.0-rc.5` descriptors and IPC results to immutable source,
  package digests, and per-file hashes. Rust composes the 96 algorithm contracts;
  [the corpus instructions](../../tests/fixtures/graphforge/core/README.md)
  reproduce the 112 retained result fixtures. This qualification concerns
  result schemas. `selectedLaunchPairing` remains unset.
- The guarded publisher covers all seven npm packages, including the browser
  package, validates aligned versions and browser asset hashes, and preflights
  existing immutable npm versions before any new upload. PyPI requires the
  complete npm cohort and both registry opt-ins. GitHub prereleases use the
  canonical version parser and cannot become the latest stable release.
- [Retained browser evidence](../performance/rc-readiness-2026-10-22/README.md)
  proves six bounded density no-refinement cases through the ESM and IIFE
  entries. The report contains exact artifact/harness hashes, screenshots,
  resource cleanup, CSP, and limitations. It does not replace the full browser
  foundation gate or the real packaged Reflex journey.
